## 1. 产品概述

### 1.1 一句话定位

GlassPane 是给 AI Agent 的运行时验证引擎：一份 Swift Engine Core（"眼和手"），两个工具面（MCP 协议面 + fork opencode 的原生面）把判定性证据送进用户自配的大模型（"脑"），外加一个从校准闭环训练出来的审美专科专家（Aesthetic Expert，下称 AE）。脑永远在用户侧，引擎和校准资产永远只有一份。

### 1.2 解决的问题

AI Agent 在 macOS 应用开发中已能完成"写码 → 静态审查 → 写静态测试"，但运行时半场——"构建 → 到达状态 → 交互 → 观察 → 诊断 → 修复 → 重验"——要么依赖低效且不可靠的"截屏 → 视觉理解 → 坐标操作"范式，要么根本缺失。GlassPane 补全这一半场，将运行时验证从"模型看图猜状态"升级为"引擎采证、模型判读"。

### 1.3 产品形态与分发

| 组件 | 形态 | 语言 |
|---|---|---|
| Engine Core | 本机常驻 Swift daemon，经 local socket 提供服务 | Swift |
| 工具面 A | MCP Server（stdio/HTTP），任何 MCP 客户端可接入 | TypeScript（壳仅协议翻译） |
| 工具面 B | opencode fork（Harness 原生面），Patch 集五薄模块 | TypeScript（上游锁定） |
| LLDB 桥 | Python 脚本（SB API）+ local socket 回传 daemon | Python |
| Aesthetic Expert | 微调服务 + Python 训练管线（PyTorch/PEFT） | Python |
| 配方（recipe） | 声明式 YAML，无解释器，agent 载入即得工作流 | YAML |
| 共享内核 | @iterate/kernel（iterate monorepo，npm 依赖，Phase B 起消费） | TypeScript |

### 1.4 三条架构铁律（产品级不变量）

1. **共享内核**：Engine Core 只有一份，两个工具面消费同一引擎；
2. **脑在外**：判定推理永远在用户自配的大模型侧，GlassPane 不内置判断型 LLM；TS 壳与 Python 管线均不承载验证推理，判定性验证逻辑 100% 位于 Swift Engine Core；
3. **资产中立**：校准资产以模型无关格式存储于 Engine Core 资产库。

## 2. 目标用户与画像

### 2.1 主画像 P1：macOS 应用开发者

- 以 SwiftUI/AppKit 为主，使用 AI Agent（Claude Code / Cursor / opencode / 任意 MCP 客户端）进行全栈开发；
- 痛点：agent 写完代码后无法自主验证运行时行为——按钮点不点得动、状态对不对、界面崩没崩，开发者要自己当"人肉测试员"；
- 问题本质：开发者能力部分（工具箱问题，可机器化）+ 用户感受部分（Oracle 问题，压缩不消灭）。

### 2.2 次画像 P2：agent 工具链生态方

- iterate 生态（iterate-harness / iterate-plugin / 第三个项目）用户：通过共享内核 @iterate/kernel 与 GlassPane 产生双向集成（见 FR-18）；
- 任意 MCP 客户端用户：不更换工作流即可获得 GlassPane 验证能力。

### 2.3 非用户（明确排除）

- 非 macOS 平台开发者（Engine Core 刚性绑定 macOS 系统运行时）；
- 仅需静态分析/单元测试、无需运行时验证的场景。

## 5. 功能需求

### FR-01 工具面 A：MCP 工具契约（阶段 P0 骨架 / P1 全量）

**六类原语**（产品级定义，与 5.5 存档清单对齐口径）：

1. **会话与目标管理**：attach 被测 app、选择被测目标、会话生命周期；
2. **感知**：AX 树读取（紧凑序列化）、state 快照、像素捕获；
3. **行动**：操作即 diff 协议（操作返回结构化变更，非截图）；
4. **断言**：八类视觉断言 + 四层 Oracle（FR-06）；
5. **诊断**：五路信号因果链查询（FR-04）；
6. **快照/恢复**：三档时间旅行（FR-08）。

**配方体系**：声明式 YAML 工作流；三源分发——内置官方配方（随引擎版本）、项目自定义（被测 app repo 内、进版本控制）、导入（文件/URL，必经 kernel 公共校验器校验）；载入失败必须可自诊断（结构化错误码+补救步骤），禁止静默半载入（综述 R35）。

**契约要求**：TS 壳仅做协议翻译（stdio/HTTP ↔ local socket）；每个工具定义参数、返回值、错误码与异常场景说明；T0 通道故障类错误可被 agent 自愈处理（联动 FR-17）。

**验收**：C28（含 5.7 扩展：kernel API 四消费者一致性）。

### FR-02 工具面 B：Harness 原生面（阶段 P1）

- fork opencode，四约束纪律：Patch 集限五个薄模块（TS，local socket 连 Swift daemon）；内核铁律（不复制引擎）；双角色时机（先薄后厚）；契约测试纪律（上游 release 自动跑，失败冻结升级）；
- 差异化能力：opencode 会话流内的原生集成（evidence 审查 UX、会话级权限引导）；
- kernel 消费（Phase B 起）：五薄模块内部 import @iterate/kernel，不新增 patch 模块、不占 Patch 集名额（综述 R32/R33）。

**验收**：C31 等（与 5.5 存档一致）。

### FR-03 感知-行动核心（阶段 P0）

- AX 树紧凑序列化与五线索引加权；
- 操作即 diff 协议；三级降级链；工作记忆外置（大状态不进模型上下文）；
- 诚实边界：不可感知区域显式声明，不猜测。

**验收**：C11/C12（观察优先级）。

### FR-04 因果链与九分类诊断（阶段 P1；T9 为 P2）

- **operationID 机制**：`act()` 生成唯一 opID，双写（TaskLocal + 进程级插槽）进被测进程；归因强度三级——软归属（第 0 环 AX 入口）/ 强归因（handler 内 Task 树）/ 弱归因（脱离 TaskLocal 的异步回调，时间窗启发式），evidence 每条显式标注；
- **并发污染防护**：操作权互斥 + CGEvent 输入流监控，检出非 agent 输入时通知暂停或降级标注 `contaminated: true`（需"输入监控"权限，拒绝时降级为纯互斥）；
- **九分类**：T0 通道故障 / T1 崩溃 / T2 假死 / T3 绑定丢失 / T4 逻辑 bug / T5 SwiftUI 依赖丢失 / T6 渲染层 bug / T7 view-model 脱节 / T8 异步时序 / T9 渐进性劣化（P2）；
- **诊断报告四段**：PATH / ANOMALY / EVIDENCE（含强/弱归因与污染标注）/ NEXT。

**验收**：C2/C7（强归因 >80%/弱 >60%，以真实 app 数据为准）；C33（P2，检出 >95%/误杀 <5%）；T9 检出（P2）。

### FR-05 白盒探针 SDK（阶段 P1；Z5 为 P0）

五级 Z 矩阵：Z1 宏插桩（低开销无反射）/ Z1b @State 直写不可插桩（诚实边界）/ Z2 Mirror / Z3 KVC / Z4.5 MTLCaptureManager / Z4 watchpoint（硬件限 4，排队策略）/ Z5 纯 AX+像素。探针安装失败输出结构化错误码+agent 补救步骤。

**验收**：C1（含宏构建膨胀：增量 <30%、全量 <50%，超标走 opt-in）。

### FR-06 视觉正确性引擎（阶段 P1）

- 八类断言 + 四层 Oracle；
- 可观测性映射表：像素 ↔ AX ↔ state 三层互证；
- 可达性标准：**28×28pt**（macOS HIG 指针点击目标；关键交互 44pt 推荐）。

**验收**：C3 等（与 5.5 存档一致）。

### FR-07 GUI 调试引擎（阶段 P1）

- LLDB 三模式（Capture/Interactive/Trace）+ 环境冻结；
- 桥形态：Python 脚本（SB API）+ local socket；C++ plugin 列为 P3 优化；
- 崩溃/假死管线：T1 崩溃帧 + 尽力快照 + 最后 AX 树 + 冻结帧；T2 主线程 ping 检出。

**验收**：C13 等（与 5.5 存档一致）。

### FR-08 状态时间旅行（阶段 P1）

- 三档：S1（档 1 全量快照恢复）/ S2（档 2 ffwd 重演）/ S3（不可用形态降级）；
- 档 1 验收：恢复保真率 ≥95%（重放原操作序列 state diff 一致比例）；恢复时间分级——小中型（≤500 状态节点）P95 <1s、大型 P95 <3s；未达标默认档降档 2；
- 不可快照区（诚实边界）显式声明。

**验收**：C34。

### FR-09 副作用观察器 + 误操作注入（阶段 P2）

- 纯净/集成双模式；观察矩阵（文件/网络/通知/剪贴板等副作用面）；
- 误操作注入受三级降级链约束（注入失败不污染被测状态）。

**验收**：C17/C21 等。

### FR-10 实际功能使用测试（阶段 P2）

- 场景卡（真实使用路径模板）；覆盖度模型（已测/未测可视化）；
- 探针 + Fuzzing 驱动的功能探索。

**验收**：C22 等。

### FR-11 UX 对人类的正确性（阶段 P2）

- 六维可计算层：响应性/可达性/一致性/辅助功能/手势/状态反馈；
- UX 五层模型映射（可计算部分与人类感受部分的边界显式声明）。

**验收**：C23/C25 等。

### FR-12 元认知引擎（阶段 P3）

引擎对自身判定质量的监控与不确定性外显（详见 5.5 存档）。

**验收**：C26 等。

### FR-13 性能熔断与降级开关（阶段 P1）

四级熔断；熔断级写入 evidence 包（消费者可见引擎负荷状态）。

**验收**：C9 等。

### FR-14 CI 形态矩阵（阶段 P1 模拟器 / P2 真机）

| 形态 | 可用性 | 关键限制 |
|---|---|---|
| 本机开发 | 全功能 | 需辅助功能权限 |
| CI 模拟器 | AX 大部分可用 | CGEvent 合成受限；无 Metal/VZ 快照；档 3 不可用 |
| CI 真机（自建 runner） | 全功能 | TCC 预授权；runner 维护成本 |
| CI 无头降级 | build+静态断言+文件系统断言 | **AX 查询不可用**（AXUIElement 依赖 GUI 会话） |

- 金丝雀回归网：八分类注入 bug 各 2–3 例，CI 模拟器形态检出率 ≥80%；
- "可进 CI"承诺按四形态分级表述，禁止跨级承诺。

**验收**：C2 联动（金丝雀检出）。

### FR-15 Oracle 治理系统（阶段 P0.5–P1）

- 七标签体系（确定性分级）；升级轨道（低确定 → 高确定流转）；基线自动失效；
- 三级人审队列：全异步（每项 ≤5 分钟、可积压、周清）；
- 评审员池：3 人配置（2 活跃+1 备份），P1 后从早期用户招募（综述 R37）。

**验收**：C27 前置（评审员间 kappa ≥0.6）。

### FR-16 审美校准引擎 + Aesthetic Expert（阶段 P0.5 启动）

- 双通道校准资产 + 两条提取通道（详见 5.5 存档 §7）；
- 训练数据规模：冷启动 200–400 张 + 每回归周期 ≤30 张 × 40 周期 ≈ 1400–1600 张；<1000 张时 C29' 开闸自动顺延；
- 部署形态：单次结构化判定（传感器调用语义）；Ø 裁决权不转移给 AE；
- 双部署质量分叉治理 + C29' 防泄漏规程（与 5.5 一致）。

**验收**：C27（校准一致率）、C29'（滚动 AB）。

### FR-17 开发者支持面（综述 §5.14，阶段 P0/P1）

- **evidence 审查 UX**（P1）：opID 证据卡片（操作/AX diff/state diff/像素 diff/归因强度/污染标注/熔断级）、按归因强度过滤、诊断报告时间线呈现；回归第一屏=失败断言汇总+待裁决 Oracle 队列；MCP 面以导出格式承载；
- **onboarding 与权限引导**（P0）：权限清单逐项声明（辅助功能/输入监控/屏幕录制/开发者工具）+ 拒绝降级形态 + 样例配方一键验证；
- **失败模式 agent 指引**（P0）：基础设施类失败输出结构化错误码+可执行补救步骤；
- **多项目与资产库**（P1）：项目注册表、资产按项目隔离、存储位置可配置。

### FR-18 iterate 生态共享内核集成（kernel Phase A–D，综述 §8.5）

- **Phase A（现在，与 P-1 并行）**：kernel 范围冻结 + npm workspaces monorepo + schema 先行（config/invariants/evidence/decision log/维度系统）；JSON Schema 唯一真源 + Swift Codable / TS zod 双绑定（状态=草案，不进 P0/P1 关键路径）；
- **Phase B（GlassPane P1 出口后）**：两个 TS 壳消费 kernel v0.1（invariants + decision log + 审计链映射 opID↔decision 单向哈希链）；
- **Phase C（C29'/C30 决策门后）**：kernel 功能提取为 opencode plugin / OpenHarness plugin；
- **Phase D（战略复盘）**：>70% 差异化价值 kernel 化时评估"一个上游+N 个面"合并（数据驱动）；
- **边界**：Swift Engine Core 不进 kernel；事务原语 kernel=编排、Swift=执行；依赖方向铁律 fork/壳 → kernel 单向；npm 依赖不占 Patch 集名额、不计入壳代码量预算；
- **双向场景**：invariant 失败触发重验（kernel 事务原语）；evidence 原生写入 iterate decision log（kernel AuditChain，无 CLI 文本解析）；维度感知上下文压缩（`dimensionContext()`）；配方挂接 iterate invariant 复核；AE provider 契约两侧同一消费。

**验收**：C35（双语言绑定 roundtrip 一致性，Phase A 就位测试）；C28 扩展（四消费者一致性 + 三分类归因）。

## 7. 数据与资产

- **evidence 包**：opID、五路信号（action/AX 事件/handler 探针/state diff/像素 diff）、归因强度（强/弱/软）、污染标注（contaminated）、熔断级——Swift 产出，JSON Schema 契约（C35）对齐 TS 侧；
- **项目注册表**：bundle id、探针配置、配方集、基线库、校准资产引用（按项目隔离）；
- **资产库**：基线（自动失效机制）、校准资产（模型无关格式）、金丝雀 app 套件；
- **审计链**：opID ↔ iterate decision log 条目单向哈希链（kernel AuditChain 类型）；
- **轨迹导出**：kernel 统一格式与写入器。
